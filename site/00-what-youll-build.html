What you'll build

A Leadpage Creator: one command in, one polished landing page out. This chapter shows you the finished thing, then walks you through the ten ideas that make it work.

By the end of this chapter

That's not a template. The agent decided on the headline, the subhead, the call-to-action, the icons, the color palette, and the page layout — but it didn't decide it alone. Several specialized parts did different bits of the work, and each one knew exactly what it was responsible for.

What's an "agent," concretely?

Forget the marketing for a second. An agent is three things:

  1. A model (Claude — Haiku, Sonnet, or Opus).
  2. A set of tools it's allowed to call (functions you defined).
  3. A loop: send a message → model thinks → either it returns text and stops, or it asks to call a tool → you call the tool → you send the result back → repeat.

That's it. Everything else — skills, subagents, memory, evals — is a pattern built on top of this loop. The reason agents feel magical is the loop, not the model. Without the loop, Claude is a sophisticated text completer. With the loop, Claude can do things. 

You ──▶ Claude ──┬─▶ text out  ──▶ done
                 │
                 └─▶ "call save_page(html='...')"
                          │
                          ▼
                     Your code runs the tool, returns the result
                          │
                          ▼
                     Back to Claude → repeats until "done"

Three pieces of vocab to know now

These three words come up in every chapter. Lock them in before moving on, because the decisions you'll make later — "should this be a tool or a skill?" — depend on knowing what each one means. 

        cheaper, simpler  ◀────────────────────────────▶  more power, more cost

        TOOL                   SKILL                   SUBAGENT
        a function the         instructions the         another agent — its
        agent can call;        agent loads on demand    own loop, its own
        stateless,             when it decides it's     context, its own
        deterministic          relevant                 goal

Smell tests (from the StockPilot workshop):

  • A tool that returns 2,000+ tokens of output? → make it code execution or a subagent instead.
  • You're writing "always do X before Y" in the system prompt? → move it into a skill.
  • The subagent's output is one number? → it shouldn't be a subagent. Make it a tool.

Two decisions you don't have to make yet

You don't have to commit to one model or one deployment target up front. We'll start with Sonnet 4.6 and a single local script. Once you have something that works, you'll pick the right model per-subagent in Chapter 08 and decide whether to host it yourself or ship it as a managed agent in Chapter 10. The whole point of the tutorial is to make those decisions measured, not pre-decided.

How to use this tutorial

  1. Read each chapter on this site.
  2. Keep a terminal open in example-agent/.
  3. Run the chapter's command. Look at the output. Read the source.
  4. Answer the checkpoint quiz to mark the chapter complete.
  5. Move to the next one.

Don't skim. The chapters are short on purpose, but each one introduces one idea you'll keep using. The "Try it" boxes are the most important part — that's where you'll see the agent actually doing something.

Checkpoint
What's the difference between "Claude" and "an agent"?
The model is the same. The "agent" part is the wrapping: a list of tools the model is allowed to ask for, and a loop in your code that actually executes those tool calls and sends the results back. You'll write that loop yourself in Chapter 03.
